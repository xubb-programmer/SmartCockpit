# 语音入口三模式与无界面唤醒词

系统支持三种语音入口模式。模式只控制语音交互入口，Web 视频、文件下载和配置页面始终保留。

| 模式 | Web语音 | 板端唤醒词 | 适用场景 |
| --- | --- | --- | --- |
| `web` | 启用 | 不启动 | 保持历史版本行为 |
| `wakeup` | 拒绝语音拨号 | 启用 | 无显示器、键盘和鼠标部署 |
| `hybrid` | 启用 | 启用 | 板端使用和远程维护并存 |

## 选择模式

编辑 `data/.config.yaml`，只需增加以下覆盖配置之一。

现有Web模式：

```yaml
voice_access:
  mode: web
```

板端唤醒词模式：

```yaml
voice_access:
  mode: wakeup
```

混合模式：

```yaml
voice_access:
  mode: hybrid
```

修改后重启：

```bash
cd /opt/jw/voice-assistant-server/scripts/deploy
./voice-assistant.sh restart qwen3-4b --no-follow
./voice-assistant.sh status
```

默认值是 `web`。没有配置 `voice_access` 的历史部署保持原行为。

## 唤醒方式

默认唤醒词：`你好小江`

推荐分两句使用：

```text
用户：你好小江
助手：短“滴”声（就绪提示）
用户：白光上电
```

唤醒检测由独立的轻量 Sherpa-ONNX KWS 模型在CPU上完成。唤醒后才向现有语音服务发送指令音频，不会启动第二套ASR、TTS或RKLLM模型。

默认采用 100 毫秒短提示音，提示音结束后保留 200 毫秒回声保护再开始收音。
请将唤醒词和实际请求分开说；当前仍为半双工，提示音或助手播报过程中说的话不会作为新请求处理。

## 何时需要再次唤醒

| 阶段 | 默认行为 |
| --- | --- |
| 首次唤醒后 | 就绪后 8 秒内开始说话；一直无声则响结束提示并休眠 |
| 正在说话 | 从检测到起音计时，单句最长 12 秒；句尾静音约 0.5 秒后提交 |
| 助手回复后 | 等待实际播放结束及回声消退，响就绪短音，开放 8 秒免唤醒续说窗口 |
| 续说成功 | 每次回复后重新开放 8 秒窗口，无需重复唤醒 |
| 续说窗口到期 | 响下降双音，之后需要再次说“你好小江” |
| 通道忙、识别为空、处理异常 | 响低双音并退出本轮；请重新唤醒重试 |

提示音：高短音表示“可以说话”；下降双音表示“已休眠”；低双音表示“本轮未完成”。
首次等待和续说窗口都从客户端真正可以收音时计算，不包含模型处理与播报耗时。
续说窗口内只在本地检测人声，检测到人声后才申请通道并上传音频；保留约 320 毫秒起音缓存，避免丢掉首字。

可在 `data/.config.yaml` 中调整：

```yaml
voice_access:
  mode: hybrid
  headless:
    acknowledgement_mode: tone       # voice 恢复“您好，请讲”
    initial_listen_timeout_seconds: 8 # 唤醒后等待开始说话
    followup_timeout_seconds: 8       # 回复后续说窗口；0 表示每轮重新唤醒
    command_timeout_seconds: 12       # 已开始说话后的最长单句时长
    speech_end_seconds: 0.5           # 句间停顿较长时可调回 0.8
    capture_chunk_ms: 40
```

## 混合模式互斥

`hybrid` 中，每个WebSocket拥有独立会话、对话历史和TTS输出。共享的ASR、RKLLM和车辆控制按完整对话轮次互斥：

1. 先取得使用权的一端开始本轮；板端首次唤醒会先申请，续说在检测到人声时申请。
2. 使用权覆盖ASR、LLM、工具调用和TTS发送。
3. 另一端立即收到“语音通道正在使用”，不会排队执行过期指令。
4. TTS完成、连接断开、识别为空或发生异常时自动释放。
5. 异常轮次最长120秒自动回收。

远程Web使用远程电脑的麦克风和扬声器；唤醒客户端使用RK3588本地音频设备，两端音频不会互相转发。
等待免唤醒续说期间不持有使用权，因此不会为 8 秒静默窗口阻塞 Web；如果续说时 Web 已在使用，则提示忙并丢弃本次请求，不排队。

## 音频设备覆盖

默认自动排除HDMI/DP并优先选择板载Codec。自动识别不正确时可覆盖：

```yaml
voice_access:
  mode: wakeup
  headless:
    input_device: plughw:2,0
    output_device: plughw:2,0
```

查看设备：

```bash
arecord -l
aplay -l
```

启动预检会检查ALSA命令、KWS模型和配置。预检失败时不会启动唤醒客户端，日志会明确指出缺少的设备、命令或模型文件。
