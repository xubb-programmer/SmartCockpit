# 语音入口三模式与无界面唤醒词

系统支持三种语音入口模式。模式只控制语音交互入口，Web 视频、文件下载和配置页面始终保留。

| 模式 | Web语音 | 板端唤醒词 | 适用场景 |
| --- | --- | --- | --- |
| `web` | 启用 | 不启动 | 保持历史版本行为 |
| `wakeup` | 拒绝语音拨号 | 启用 | 无显示器、键盘和鼠标部署 |
| `hybrid` | 启用 | 启用 | 板端使用和远程维护并存 |

## 选择模式

编辑 `data/.config.yaml`，只需增加以下覆盖配置之一。

现有Web模式：

```yaml
voice_access:
  mode: web
```

板端唤醒词模式：

```yaml
voice_access:
  mode: wakeup
```

混合模式：

```yaml
voice_access:
  mode: hybrid
```

修改后重启：

```bash
cd /opt/jw/voice-assistant-server/scripts/deploy
./voice-assistant.sh restart qwen3-4b --no-follow
./voice-assistant.sh status
```

默认值是 `web`。没有配置 `voice_access` 的历史部署保持原行为。

## 唤醒方式

默认唤醒词：`你好小江`

推荐分两句使用：

```text
用户：你好小江
助手：您好，请讲
用户：白光上电
```

唤醒检测由独立的轻量 Sherpa-ONNX KWS 模型在CPU上完成。唤醒后才向现有语音服务发送指令音频，不会启动第二套ASR、TTS或RKLLM模型。

## 混合模式互斥

`hybrid` 中，每个WebSocket拥有独立会话、对话历史和TTS输出。共享的ASR、RKLLM和车辆控制按完整对话轮次互斥：

1. 最先检测到有效语音的一端取得本轮使用权。
2. 使用权覆盖ASR、LLM、工具调用和TTS发送。
3. 另一端立即收到“语音通道正在使用”，不会排队执行过期指令。
4. TTS完成、连接断开、识别为空或发生异常时自动释放。
5. 异常轮次最长120秒自动回收。

远程Web使用远程电脑的麦克风和扬声器；唤醒客户端使用RK3588本地音频设备，两端音频不会互相转发。

## 音频设备覆盖

默认自动排除HDMI/DP并优先选择板载Codec。自动识别不正确时可覆盖：

```yaml
voice_access:
  mode: wakeup
  headless:
    input_device: plughw:2,0
    output_device: plughw:2,0
```

查看设备：

```bash
arecord -l
aplay -l
```

## 检查和日志

```bash
cd /opt/jw/voice-assistant-server
source /home/jw/miniconda3/etc/profile.d/conda.sh
conda activate voice-assistant-server
VOICE_ACCESS_MODE=wakeup python3 clients/headless_voice_client.py --check

tail -f /tmp/headless_voice_client.log
scripts/deploy/voice-assistant.sh status
```

启动预检会检查ALSA命令、KWS模型和配置。预检失败时不会启动唤醒客户端，日志会明确指出缺少的设备、命令或模型文件。
