# 车载多模态智能交互系统性能指标说明

## 一、说明

本文档用于说明车载多模态智能交互系统在 RK3588 平台上的主要性能指标、测试口径和建议验收方式。指标以当前版本在 RK3588 板端的实际运行日志为主要依据，并区分典型实测值、建议验收值和异常恢复样本。

## 二、测试环境

| 项目 | 配置 |
| --- | --- |
| 硬件平台 | RK3588 开发板 |
| 推理方式 | 本地离线推理 |
| 语音识别 | 离线 ASR 模型 |
| 语音合成 | 离线 TTS 模型 |
| 文本大模型 | Qwen3.5-0.8B RKLLM W8A8 量化模型 |
| 视觉分析 | Qwen3.5 多模态 RKLLM + RKNN 视觉编码器 |
| 访问方式 | 本机浏览器或局域网 HTTPS/WSS Web 客户端 |
| 网络环境 | 局域网环境，客户端与 RK3588 位于同一网段 |

说明：当前板端实测运行模型为 Qwen3.5-0.8B RKLLM W8A8，最大上下文 4096 tokens，文本输出上限 256 tokens；视觉编码器输入尺寸为 448x448，视觉输出上限 96 tokens。

## 三、性能指标定义

| 指标 | 定义 |
| --- | --- |
| 服务启动时间 | 从执行启动脚本到核心服务、Web 服务和模型服务全部就绪的时间 |
| ASR 识别延迟 | 用户语音结束后，到系统输出识别文本的时间 |
| 语义理解延迟 | 识别文本进入大模型后，到生成回复或工具调用结果的时间 |
| 控制指令响应延迟 | 用户语音结束后，到系统完成车辆控制指令下发的时间 |
| TTS 首包延迟 | 回复文本生成后，到前端收到首个可播放音频帧的时间 |
| Web 视频播放延迟 | 摄像头视频流到 Web 页面显示之间的端到端延迟 |
| 视觉分析延迟 | 最新视频帧进入视觉分析接口后，到输出画面分析文字的时间 |

## 四、当前实测指标与异常样本

以下数据来自 2026 年 8 月 28 日 RK3588 板端运行日志，访问入口为 HTTPS/WSS Web 客户端，车辆控制接口位于同一局域网内。数值用于反映当前版本在实际演示环境中的典型表现。

| 指标 | 当前实测参考 | 建议验收值 | 说明 |
| --- | --- | --- | --- |
| 服务启动时间 | 约 60-90 秒 | 不超过 120 秒 | 包含模型加载、NPU 初始化、Web HTTP/HTTPS 服务启动 |
| Web 页面打开时间 | 约 1-3 秒 | 不超过 5 秒 | 局域网 HTTPS 访问，首次自签名证书确认时间不计入 |
| ASR 识别延迟 | 约 0.24-0.27 秒 | 不超过 1 秒 | 普通短句语音，VAD 判定一句话结束后开始统计 |
| 语义理解与工具调用延迟 | 约 1.5-1.9 秒 | 不超过 5 秒 | 典型指令包括“白光上电”“白光什么状态” |
| 语音控制首响应延迟 | 约 1.8-2.8 秒 | 不超过 5 秒 | 从识别文本进入对话到前端收到首个音频帧 |
| 控制接口下发延迟 | 小于 1 秒 | 不超过 2 秒 | vehicle_control / vehicle_status HTTP 接口在同一秒完成返回 |
| TTS 合成延迟 | 短句约 0.2-0.4 秒，长句约 1.1 秒 | 不超过 2 秒 | 不含音频按时长播放所需的自然播放时间 |
| Web 视频播放延迟 | 低延时配置下约 0.2 秒级 | 不超过 1 秒 | 以当前 Web 低延时播放配置和局域网视频流为依据 |
| 视觉分析延迟 | 约 16.2-18.5 秒，最近一次 18.452 秒 | 不超过 20 秒 | Qwen3.5-0.8B 多模态本地推理，命中图像编码缓存 |
| 连续运行稳定性 | 支持长时间连续运行 | 不少于 8 小时 | 无服务崩溃、端口异常占用或模型进程异常退出 |

## 五、当前实测参考

当前版本在 RK3588 上已启用 HTTPS/WSS 同源访问、视频帧上传、Qwen3.5 多模态视觉分析和低延时视觉参数。当前日志中的典型测试结果如下：

| 测试项 | 实测结果 |
| --- | --- |
| 视觉模型 | Qwen3.5-0.8B RKLLM + 448x448 RKNN 视觉编码器 |
| 视觉输出上限 | 96 tokens |
| 图像编码缓存 | 已启用 |
| 单次视觉分析接口耗时 | 约 16.2-18.5 秒，最近一次 18.452 秒 |
| 视觉图像编码耗时 | 后台预编码约 0.73-0.80 秒，命中缓存后本次接口为 0 秒 |
| 主要耗时来源 | RKLLM 多模态生成阶段 |

车辆控制与状态查询典型日志结果如下：

| 测试项 | 实测结果 |

## 六、异常样本与修复验证

日志中曾出现一次“白光什么状态”耗时 27.279 秒的异常样本。该次请求前一条视觉推理耗时 16.090 秒，并出现 `rkllm_run failed: -1`；随后文本请求检测到 2 条未同步历史消息，旧逻辑执行了 prefill-only 历史 KV 补写，RKLLM 首 token 又耗时 14.133 秒，最终造成语音服务侧 LLM 总耗时约 27.279 秒。

该异常中设备状态 HTTP 接口在同一秒内完成返回，说明慢点位于 RKLLM 历史 KV 补写和异常状态恢复，不在车辆控制接口。相邻正常样本如下：

| 测试项 | 正常实测结果 |
| --- | --- |
| “白光上电” LLM 工具调用 | 约 1.8-1.9 秒 |
| “白光上电”首个音频响应 | 约 2.3-2.8 秒 |
| “白光什么状态” LLM 工具调用 | 约 1.5-1.6 秒 |
| “白光什么状态”首个音频响应 | 约 1.8 秒 |

当前修复已移除异常历史消息的慢速 prefill-only 路径，并在 RKLLM 运行异常后执行 `abort`、清理对话 KV 和输出队列，避免异常状态拖慢下一条控制指令。修复已完成本地语法与相关测试，并已同步到 RK3588；最终验收需在板端连续执行控制指令后，以日志中的 `[性能][LLM]`、`[性能][RKLLM]` 和 `RUN_ERROR` 记录为准。

该实测结果用于说明现阶段本地多模态理解能力已经可用，但视觉分析不建议作为毫秒级实时控制链路使用。实时驾驶、控制或告警类场景应优先使用专用目标检测、规则判断或传感器数据接口。

## 七、验收建议

1. 每项延迟测试建议连续执行不少于十次，记录平均值、最大值和第九十五百分位值。
2. 控制类指令建议覆盖上电、下电、调焦、变倍、扫描、停止、开关增强、开关十字丝等典型操作。
3. 视频类测试建议分别覆盖 RTSP 和 RTMP 地址，记录首帧时间、播放连续性和端到端画面延迟。
4. 视觉分析测试应在视频持续播放并持续上传最新帧的条件下进行，避免使用过期截图。
5. 对外提交材料建议使用保守值作为承诺指标，将更优的现场测试结果作为补充记录。
